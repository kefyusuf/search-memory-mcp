# ADR-0002: Public multi-user service boundaries

Date: 2026-10-02
Status: Accepted design; context, dispatcher and scoped SQLite memory/graph/knowledge/private caches implemented; hosted adapters pending

## Context

The first live target is an internet-facing multi-user product. The current server is a local stdio process with a shared SQLite path, process-wide provider health/rate limits, and client-supplied note session labels. These are not authentication or tenant boundaries. The [production roadmap](../production-roadmap.md) defines release gates.

## Decision

Start with a single-region modular service and bounded resource-intensive workers. Retain stdio as a local development/distribution transport. Extract transport-independent tool handlers before adding public HTTP routing; public access is blocked until authentication, authorization, data isolation and resource budgets are verified.

The HTTP adapter must derive an authenticated principal and workspace membership from validated credentials. It passes an immutable request context to every handler: tenant/workspace id, principal id, granted permissions, request id, deadline and cancellation signal. Caller-supplied `session`, document ids, URLs and cache keys must never override that context.

Storage contracts must require tenant context for notes, documents, chunks, graph entities and private cache entries. A PostgreSQL-backed store with tenant-aware vector retrieval is the hosted implementation candidate; selection is finalized through migration, load and restore evidence. SQLite remains an optional local adapter, not a shared file for horizontal replicas.

Browser contexts, queued jobs, deduplication keys and quotas must respect the same boundary. Shared public-content caching requires an explicit separate policy; private input and local-index data cannot enter it. Provider/model/fetch work is bounded independently of the tool-call count.

Target MCP protocol/client support must be explicit. The installed v1 SDK supports the 2025-era protocol; adding the 2026-07-28 revision requires a tested migration and compatibility strategy. This ADR does not claim newer protocol support.

## Required acceptance scenarios for the next implementation slice

Implemented foundation: a server-issued immutable context and transport-independent dispatcher check permissions, provenance, auth expiry, execution mode, deadline and cancellation before executing a handler. The stdio adapter uses this path. All existing handlers explicitly allow only local mode because hosted storage and budgets remain incomplete. The hosted context factory accepts already-verified authorization and trusted membership outputs; token signature/issuer verification and HTTP/OAuth integration are still required. Preflight cancellation is implemented; cancellation during running work is not.

SQLite session memory now accepts a trusted context, rechecks its validity and read/write permissions on every operation, and filters get/list/search/delete/clear/stats/eviction by execution mode, tenant and workspace. Legacy callers without a context use the local scope; adapters for hosted requests must always provide one. Matching session labels or workspace names in different tenants cannot cross this boundary. This is an isolation reference implementation, not a hosted database selection or proof of multi-replica durability. Browser resources and quotas still require their own boundaries.

Entity graph storage follows the same trusted-context rule. Document ids, entity ids/names and links have composite scope keys, and every join includes matching execution mode, tenant and workspace. Ownership filtering happens before ranking/limit. Indexing requires knowledge:write; entity/document/neighbor lookup and stats require knowledge:read. The legacy schema is rebuilt and copied into the local scope in one transaction, preserving existing links and counts. Hosted/local modes stay separate even if tenant/workspace names equal local. Existing tool registrations remain local-only; hosted graph routing and hosted storage operations are not enabled.

The additive migration assigns legacy rows to the local/local/local scope and creates a scope index in one transaction; writes and scoped eviction are also transactional. Once hosted rows exist, running an older binary against that database is unsafe because old queries ignore ownership columns. Any rollback must preserve scoped-query enforcement, or restore a pre-migration local-only backup into a separate local database. Production backup/restore, journal policy and migration operations remain release gates.

- Missing, expired, wrong-audience and insufficient-permission credentials cannot call protected tools.
- A principal without workspace membership cannot read/write that workspace.
- Tenant A cannot read, update, delete, recall, relate or retrieve tenant B's data through an id, source, session label, semantic match or queued job.
- Private cache entries cannot cross workspace boundaries even when queries have identical embeddings.
- Limits hold across concurrent requests and query variants; cancellation releases browser/job slots.
- Restore preserves tenant ownership and relationships; disabling a provider or reverting a release does not bypass permissions.

Write failing tests for these scenarios as the corresponding HTTP/storage boundaries are implemented. This document records design decisions and test requirements; the current code does not yet satisfy these public-service gates.

## Consequences

TransformersEmbeddingProvider publishes one lazy loader promise before starting model initialization. Concurrent calls on that provider await the same success/failure, and subsequent calls reuse the loaded extractor. Load failure remains sticky per provider and returns empty embeddings; inference failure propagates without marking the loader unavailable or triggering a reload. KnowledgeIndex now owns one lazy provider promise shared by document embedding jobs and default vector queries; custom query embeddings and FTS-only indexes bypass initialization. A load/import failure therefore degrades later work on that index without document-triggered automatic reload; deliberate retry/recovery is not implemented. Separate provider/index instances do not share weights, identity, results or lifecycle. This is not a process-wide registry, inference concurrency limiter, disposal/readiness contract or real-model resource measurement.

KnowledgeIndex reserves a bounded number of active plus queued embedding chunks per instance. maxPendingEmbeddingChunks is a positive safe integer with a local default of 256. Capacity checks precede document/chunk/FTS writes; embedding_queue_full rejects the whole ingest rather than silently accepting partial data. SQL rollback reserves nothing. Serialized embedding jobs release their full reservation in finally after settlement, including inference failures, context rejection or close. Deleting a document does not immediately refund pending work. FTS-only indexes skip scheduling. These reservations are process-local and instance-local, not shared tenant quotas, input/storage byte limits, model single-flight/concurrency controls, inference deadlines or durable job leases. Hosted deployment must explicitly size and coordinate these additional boundaries.

InMemoryInvocationAdmission optionally accepts explicit sliding-window rate limits with global, tenant, workspace and principal budgets and one windowMs duration. Every field must be a positive safe integer and is snapshotted. performance.now supplies monotonic time; each accepted timestamp expires independently at the window boundary, avoiding wall-clock resets or fixed-window bursts. Rate dimensions use the same trusted scope keys as concurrency. All rate/concurrency checks precede charges; rejection consumes neither budget. Accepted invocations consume rate usage even if their handlers fail or are cancelled; grant release only restores concurrency. Sweeping all expired identity histories on admission checks bounds retained timestamp state to at most four times global accepted usage in the window; idle state stays bounded until another check. Rejected ingress attempts still require an HTTP/IP abuse boundary. Omitting rateLimits preserves concurrency-only behavior, so hosted bootstrap must configure the intended rate policy explicitly. This remains a process-local reference, not durable/distributed quota evidence.

Hosted tool dispatch now requires an explicit InvocationAdmission policy, shared by all hosted dispatchers in the process; absent policy fails with admission_unavailable. InMemoryInvocationAdmission is a process-local reference with explicit positive safe-integer global, tenant, workspace and principal limits. Workspace keys include tenant; principal limits span tenants/workspaces for the authenticated subject. Every invocation counts, including repeated request IDs, and caller arguments cannot select buckets. All dimensions are checked before any counter changes; released empty buckets are removed. Local calls bypass this hosted policy, so shared local/hosted worker resource budgets still require their own boundary.

Admission may be asynchronous for future shared implementations. The dispatcher rechecks context after grant acquisition, after handler completion and after grant release. Grants are released in finally after successful or failed handler settlement, not immediately on abort: releasing while an uncancellable handler still runs would undercount work. This bounds admitted invocations in one process, not provider/model/fetch work within a call. Distributed admission, lease/crash recovery, rate/IP/signup/batch ingress limits, spend budgets, forced cancellation and policy/bootstrap wiring remain release gates. An asynchronous admission adapter owns cleanup for acquisition failure/cancellation and reliable release; no distributed adapter is implemented here. Built-in tools stay local-only.

Private cache storage binds content URLs and vector metadata to trusted mode/tenant/workspace ownership, independently of client-controlled metadata and search execution namespaces. Hosted physical vector keys hash the scope and logical id; legacy local ids are preserved and cannot overwrite an existing foreign key. Native and JS fallback searches apply both ownership and namespace constraints before ranking/limits. Schema migration preserves local content, metadata and vectors. Clear is a scoped transaction across both persisted vector backends and content; statistics count owned records across both vector backends.

Cache fills are internal effects of read tools: search:read permits search cache lookup/fill and content:read permits content lookup/fill. No raw hosted cache-write tool is exposed. status:read permits owned statistics; cache:manage is required for clear and TTL cleanup. A future maintenance worker must receive an explicit scoped grant; an expired user request must not become background authority. Hosted cache adapters must implement IVectorStore.assertAccess (optional only for legacy local implementations), and enforce ownership on each storage operation. SemanticCache checks access before/after inference waits and propagates InvocationError instead of silently converting authorization/cancellation into cache miss. Resource/model cancellation and quotas remain separate requirements.

Knowledge document ownership is the authoritative boundary for chunks, FTS rows and vectors: globally unique opaque document/chunk ids join back to mode/tenant/workspace before ordering and limits. Legacy ids and indexes are preserved; the additive document migration assigns legacy ownership to local/local/local. Each data API checks context and read/write permissions. Deletion selects/removes vectors before chunks, and queued embedding writes atomically check surviving ownership. Query waits recheck context before returning. This reference adapter retains a shared FTS corpus and brute-force vector scan; workspace-only ranking statistics, bounded work and a hosted storage adapter are not demonstrated by these isolation tests. No hosted tool registration is enabled by this change.

Cache correctness can ship independently as a local/server-core fix. Public deployment requires additional PRs for request context, handler extraction, storage ownership, HTTP/auth and operational controls. Neither this foundation PR nor passing local tests authorizes a public launch.
